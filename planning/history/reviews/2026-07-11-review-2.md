## Critical (1)

### 1. [SILENT]+[TEST] hooks/lib/toon-writer.ts:29 + hooks/lib/toon-reader.ts:110 — Round-trip asymmetry: writer emits escapes the hooks reader never decodes
The writer mirrors `lib/toon.ts` `encodeScalar` (backslash escapes: `\`→`\\`, tab→`\t`, newline→`\n`, control chars→`\uXXXX`; embedded quotes→`""`), but the hooks read path (`parseValue` at toon-reader.ts:110–126 + `splitCsvLine`) only strips surrounding quotes and collapses `""` mid-row — no backslash decode, and a naive leading/trailing-quote slice. Verified failures: `back\slash` reads back doubled; a cell whose value starts+ends with a quote char (`"already"`) loses both outer quotes; embedded tab/newline read back as literal 2-char sequences.
**Reachability**: `filesChanged` comes from `git diff-tree --name-only`; git's `core.quotePath` output for unicode paths contains literal backslashes (`"src/\303\251.ts"`), which corrupt on the ledger's read-modify-write cycle and **compound with each commit**. The hook's intentional fail-open catch makes the corruption invisible at every layer. Security notes this is fidelity corruption, not injection (`splitCsvLine` keeps quoted content intact).
**Fix**: port `lib/toon.ts` `decodeScalarToken` semantics (backslashDecode + `""`-collapse) into `toon-reader.ts` `parseValue`, and add round-trip tests for backslash / tab / newline / leading-trailing-quote / git-quoted-unicode cells to `hooks/__tests__/toon-writer.test.ts` (they fail today).
*Found by: silent-failure-hunter (CRITICAL 1+2), pr-test-analyzer (GAP 1), security-reviewer (sec-001, CWE-116, info corroboration)*
